# WYZ0201: Check that a Maybe has a value before calling GetValue()

| | |
|---|---|
| Category | Usage |
| Default severity | Warning |

## Cause

`GetValue()` is called on a `Maybe<T>` where nothing guarantees that it has a value:

```csharp
int value = maybe.GetValue();         // throws InvalidOperationException when the maybe has no value
var first = Find().GetValue();        // a call result cannot be checked first
```

## Why it matters

A maybe is a value that is either present or absent, and `GetValue()` is only meaningful in the first state. In the second it
throws, which is exactly the kind of failure the maybe type exists to avoid.

## How to fix

Check first. The analyzer recognises these guards for the *same* variable, field or property:

```csharp
if (maybe.IsSome)
{
    Use(maybe.GetValue());                    // inside the if
}

if (maybe.IsNone)
{
    return;                                   // an earlier if that leaves the block
}

var value = maybe.GetValue();

var text = maybe.IsSome ? maybe.GetValue().ToString() : "none";   // conditional, && and || are understood too

if (maybe.TryGetValue(out _)) { var v = maybe.GetValue(); }       // TryGetValue counts as a check
```

Better still, avoid the accessor: `TryGetValue`, `ValueOr`, `Match` and the railway methods (`Map`, `Bind`, `Filter`, `Tap`) never
throw for the absent state.

```csharp
if (maybe.TryGetValue(out var value)) { Use(value); }

var number = maybe.ValueOr(0);

var text = maybe.Match(v => v.ToString(), () => "none");
```

## When to suppress

Tests often assert on the value right after asserting `IsSome`. Lower the severity for test projects:

```ini
[**/*Tests*/**.cs]
dotnet_diagnostic.WYZ0201.severity = none
```

The analysis is syntactic and local: it does not follow a maybe through another method or a reassignment between the check and
the call, and a check outside a local function does not guard a call inside it. Suppress a single call with
`#pragma warning disable WYZ0201` when you know better.

## What is not reported

A `default` maybe is a valid none, and ignoring a maybe is harmless (a `Tap` chain ends in one), so there are no rules for those.

## Code fix

There is none. Where a check belongs, and what the code should do when the check says no (return, throw, use a default,
log), is a decision about the surrounding code, and wrapping the call in an `if` would leave the "else" undefined.
Pick the form that fits: an `if` on `IsSome`/`IsNone`, `TryGetValue`, `ValueOr`, or `Match`.
