# WYZ0203: Use ValueOr instead of a conditional on IsSome

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A conditional expression that tests whether a maybe has a value, and returns the value of that maybe or something else:

```csharp
var quantity = line.IsSome ? line.GetValue() : 1;
var quantity = line.IsNone ? 1 : line.GetValue();
```

## Why it matters

`ValueOr` is that sentence: the value, or this instead. It also removes the `GetValue()` that [WYZ0201](WYZ0201.md) would otherwise ask you to guard.

## How to fix

```csharp
var quantity = line.ValueOr(1);
```

## What is left alone

- A fallback that costs something or can change something: a call, an allocation, a property. The conditional evaluates the fallback only for none,
  and `ValueOr` always does, so the rule reports a fallback only when it is a constant, a local, a parameter or a field. (`ValueOr` with a function
  evaluates it only for none, but a function that captures a variable allocates a delegate on every call, so the rule does not suggest it.)
- A conditional that reads another maybe, one that does something to the value (`m.GetValue() + 1`), one with a receiver that is a call (the call would
  be evaluated again), and one whose branches are the wrong way round (`IsNone ? m.GetValue() : x`).

## Code fix

Yes. The fix writes `receiver.ValueOr(fallback)`, and works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0203.severity = warning   # or none
```
