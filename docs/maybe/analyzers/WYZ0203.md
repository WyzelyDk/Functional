# WYZ0203: Use ValueOr instead of a conditional on IsSome

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A conditional expression that tests whether a maybe has a value, and returns the value of that maybe or something else:

```csharp
var quantity = line.IsSome ? line.GetValue() : 1;
var quantity = line.IsNone ? 1 : line.GetValue();
```

## Why it matters

`ValueOr` is that sentence: the value, or this instead. It also removes the `GetValue()` that [WYZ0201](WYZ0201.md) would otherwise ask you to guard.

## How to fix

A fallback that is cheap (a constant, a local, a parameter or a field) becomes the value itself.
Any other fallback becomes a function, which `ValueOr` runs only when there is no value, like the conditional does:

```csharp
var quantity = line.ValueOr(1);
var label = line.ValueOr(() => LoadDefaultLabel());
```

## What is left alone

- A fallback that cannot be a function: one that throws, is a target-typed `new()`, one that awaits, passes something by `ref` or `out`,
  declares a variable (`out var n`, `is int n`),
  or reads a `ref`, `out` or `in` parameter, a `ref` local, a `Span<T>` or another `ref` struct, or the instance of a struct,
  because a lambda cannot capture those.
  Such a fallback is reported only when it is cheap.
- A fallback that does work in a maybe of `object`, a `Delegate`, a delegate type or an expression tree (and `dynamic`, to stay on the safe side):
  a lambda converts to those, so `ValueOr(() => x)` would pick the overload that takes the value and return the function itself.
- A fallback that has no type of its own, a target-typed `new()`: it converts to every overload of `ValueOr` that takes a function,
  and the compiler reports the call as ambiguous.
- A conditional whose type is not the type of the value (`m.IsSome ? m.GetValue() : 1.5` on a `Maybe<int>` is a `double`),
  one that reads another maybe, one that does something to the value (`m.GetValue() + 1`),
  one with a receiver that is a call (the call would be evaluated again), and one whose branches are the wrong way round (`IsNone ? m.GetValue() : x`).

## Code fix

Yes. The fix writes `receiver.ValueOr(fallback)` for a cheap fallback and `receiver.ValueOr(() => fallback)` for any other, and works with "fix all".

The same sentence written as a `Match` is [WYZ0205](WYZ0205.md), and a `ValueOr` whose fallback does work is [WYZ0208](WYZ0208.md).

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0203.severity = warning   # or none
```
