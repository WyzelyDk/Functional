# WYZ0206: Use Map instead of a Bind that only wraps the value in Some

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Bind` whose delegate always returns `Maybe.Some` of a value of a value type
(a number, a `bool`, a `DateTime`, an enum, a tuple, your own struct, or a type parameter with the `struct` or `unmanaged` constraint):

```csharp
var total = line.Bind(order => Maybe.Some(order.Quantity * 2));
```

## Why it matters

`Bind` is for steps that can come back with none. A delegate that always has a value is a `Map`, which takes the value itself and does the wrapping.

## How to fix

```csharp
var total = line.Map(order => order.Quantity * 2);
```

## What is left alone

- A value of a reference type (`Maybe.Some(order.Name)`) and a nullable value type (`Maybe.Some((int?)x)`).
  `Maybe.Some` throws for `null`, while `Map` turns a `null` into none, so the two are not the same when the value can be `null`.
  The rule reports only a value that can never be `null`.
- A value of a type parameter without the `struct` or `unmanaged` constraint, because it can be a reference type.
- A delegate that returns the value it was given (that is [WYZ0207](WYZ0207.md)), `Maybe.Some<object>(x)` with a type argument that differs
  from the type of the value (the type of the maybe would change), an `async` delegate, a delegate that returns anything else than a call of `Maybe.Some`,
  and a call that is not written as `receiver.Bind(...)`.

## Code fix

Yes. The fix renames the call and removes the `Maybe.Some(...)` around the returned value, and works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0206.severity = warning   # or none
```
