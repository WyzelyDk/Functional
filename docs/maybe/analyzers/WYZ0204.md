# WYZ0204: Use Maybe.From instead of a null check

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A conditional on a null check that gives none for `null` and `Maybe.Some` of the same value otherwise:

```csharp
Maybe<string> name = text is null ? Maybe.None<string>() : Maybe.Some(text);
Maybe<int> count = number is null ? Maybe.None<int>() : Maybe.Some(number.Value);
```

## Why it matters

`Maybe.From` is that: none for `null`, otherwise a maybe that holds the value. It exists for a reference and for a nullable value type.

## How to fix

```csharp
Maybe<string> name = Maybe.From(text);
Maybe<int> count = Maybe.From(number);
```

## What is left alone

A conditional that does something to the value (`Maybe.Some(text.Trim())`), a branch that is not none or not `Some` of the checked value, a comparison with
anything but `null`, and a checked expression that is a call.

## Code fix

Yes. The fix writes `Maybe.From(value)`, and works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0204.severity = warning   # or none
```
