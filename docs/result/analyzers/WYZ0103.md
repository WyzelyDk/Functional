# WYZ0103: Use BindIf instead of a condition inside Bind

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Bind` whose delegate returns the value in a successful result for one branch of a condition, and another result for the other branch:

```csharp
result.Bind(order => IsExpress(order) ? Reserve(order) : Result.Success(order));
```

## Why it matters

That is what `BindIf` is: run the operation when the condition holds, and otherwise keep the result as it was. The name says it, the delegate no longer
repeats `Result.Success(order)`, and a result that is not a success is still passed through without evaluating the condition.

## How to fix

```csharp
result.BindIf(order => IsExpress(order), order => Reserve(order));
```

The condition stays lazy, exactly as it was: it is a function that runs only for a successful result. When the condition does not read the value, the fix
writes it as `() => condition`. When the branches are the other way round (`condition ? Result.Success(x) : f(x)`), the fix negates the condition.

## What is left alone

- A branch that is a failure (`Result.Failure(...)`): that is a validation, which `Ensure` and `EnsureNotNull` say better.
- A branch that is `Result.Success` of something other than the value, and delegates with more than one statement.

## Cost

The rewrite has two small lambdas where there was one. A lambda that captures a variable allocates a delegate, as the original did.

## Code fix

Yes. The fix rewrites the call as shown, and works with "fix all in document, project or solution".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0103.severity = warning   # or none
```
