# WYZ0109: Use SuccessIf or FailureIf instead of a conditional expression

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A conditional expression that is a success for one branch and a failure for the other:

```csharp
return isAdult ? Result.Success() : Result.Failure(tooYoung);
```

## Why it matters

`Result.SuccessIf(condition, error)` and `Result.FailureIf(condition, error)` are that expression, named after what they do.

## How to fix

```csharp
return Result.SuccessIf(isAdult, tooYoung);
```

When the success is in the second branch, the fix uses `FailureIf`.

## What is left alone

An error that is not a constant, a local or a field: `Result.Failure(Error.Create(...))` in a branch creates the error only when it is needed, while the
rewrite would either create it on every call, or pass a function, which allocates a delegate on every call. Code like that stays as it is. Results with a value
(`Result.Success(value)`) have no `SuccessIf`.

## Code fix

Yes. The fix rewrites the call as shown, and works with "fix all in document, project or solution".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0109.severity = warning   # or none
```
