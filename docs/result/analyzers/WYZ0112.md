# WYZ0112: Use Map instead of a Bind that only wraps the value in Result.Success

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Bind` whose delegate always returns `Result.Success` of some value:

```csharp
result.Bind(order => Result.Success(order.Total * 1.25m));
```

## Why it matters

`Bind` is for steps that can fail. A delegate that cannot fail is a `Map`, which takes the value itself and does the wrapping.

## How to fix

```csharp
result.Map(order => order.Total * 1.25m);
```

## What is left alone

A delegate that returns the value it was given (that is [WYZ0115](WYZ0115.md)), `Result.Success<object>(x)` with a type argument that differs
from the type of the value (the type of the result would change), an `async` delegate, and a call that is not written as `receiver.Bind(...)`.

## Code fix

Yes. The fix renames the call and removes the `Result.Success(...)` around the returned value, and works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0112.severity = warning   # or none
```
