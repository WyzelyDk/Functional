# WYZ0116: Pass the message to Result.Failure instead of creating the error

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

`Result.Failure` or `Result.Failure<T>` with an error that is created from a message, and nothing else:

```csharp
return Result.Failure(Error.Create("The basket is empty."));
```

## Why it matters

`Result.Failure(string)` creates exactly that error. The shorter form says the same and has one call less to read.

## How to fix

```csharp
return Result.Failure("The basket is empty.");
```

## What is left alone

An error with a kind (`Error.Create(message, ErrorKind.NotFound)` and `Error.NotFound(message)`), where the error is the point, and a message that
is the `null` literal, because the call would be ambiguous between the two overloads.

## Code fix

Yes. The fix replaces the argument with the message, and works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0116.severity = warning   # or none
```
