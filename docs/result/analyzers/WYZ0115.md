# WYZ0115: Remove a step that does not change the result

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Map` that returns the value it was given, or a `Bind` that wraps it in `Result.Success` again:

```csharp
result.Map(order => order);
result.Bind(order => Result.Success(order));
```

## Why it matters

The call returns a result with the same value and the same type, so it does nothing, and it is a step that a reader has to understand before they
can skip it. It often stays behind after a refactoring.

## How to fix

Remove the call:

```csharp
result
```

## What is left alone

A step whose type changes (`Map<int, object>(x => x)`, `Result.Success<object>(x)`), a step that does anything else with the value, and an
`async` delegate.

## Code fix

Yes. The fix replaces the call with the result it was called on, and works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0115.severity = warning   # or none
```
