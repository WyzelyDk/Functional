# WYZ0104: Use MapIf instead of a condition inside Map

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Map` whose delegate returns the value itself for one branch of a condition, and a new value of the same type for the other branch:

```csharp
result.Map(price => IsMember(price) ? price * 0.9m : price);
```

## Why it matters

That is what `MapIf` is: transform the value when the condition holds, and otherwise keep it. The condition is lazy in both forms: it runs only for a
successful result.

## How to fix

```csharp
result.MapIf(price => IsMember(price), price => price * 0.9m);
```

When the condition does not read the value, the fix writes it as `() => condition`, and when the branches are the other way round it negates the condition.

## What is left alone

A conditional whose other branch has another type than the value: `MapIf` keeps the type of the value (`T` to `T`), so the rewrite would not compile.

## Code fix

Yes. The fix rewrites the call as shown, and works with "fix all in document, project or solution".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0104.severity = warning   # or none
```
