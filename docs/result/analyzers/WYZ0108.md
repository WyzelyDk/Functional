# WYZ0108: Use ConvertFailure to pass a failure on as another type

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A failed result of another value type is created from the error of a result:

```csharp
if (found.IsFailure)
{
    return Result.Failure<Order>(found.GetError());
}
```

## Why it matters

`ConvertFailure<T>()` says it directly. It throws exactly when `GetError()` does (for a successful result), so it needs the same check, and WYZ0102 asks for it.

## How to fix

```csharp
if (found.IsFailure)
{
    return found.ConvertFailure<Order>();
}
```

## What is left alone

`Result.Failure(...)` without a value type, and any failure that is created from something other than `GetError()` of a result.

## Code fix

Yes. The fix rewrites the call as shown, and works with "fix all in document, project or solution".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0108.severity = warning   # or none
```
