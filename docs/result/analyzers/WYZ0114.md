# WYZ0114: Use ValueOr instead of a Match that returns the value or a fallback

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Match` on a `Result<T>`, or on a `Task` or `ValueTask` of one, that returns the value for a success and a fallback for a failure:

```csharp
var count = result.Match(value => value, _ => 0);
var label = result.Match(value => value, error => $"unavailable: {error.Message}");
```

## Why it matters

`ValueOr` is that sentence: the value, or this instead.

## How to fix

A fallback that is cheap and does not read the error becomes the value itself.
Any other fallback stays a function, which `ValueOr` runs only for a failure, like `Match` does:

```csharp
var count = result.ValueOr(0);
var label = result.ValueOr(error => $"unavailable: {error.Message}");
```

On a `Task` or a `ValueTask`, a `null` or `default` literal as the fallback is not reported, because it has no form that compiles there without a type:
as an argument and as the result of a function it is ambiguous (`CS0121`), see [a `null` or `default` literal](../async.md#a-null-or-default-literal).

## What is left alone

- A success delegate that does something to the value, `Match` with a result type that differs from the type of the value,
  and a failure delegate that is not a lambda (a method group, for example), or that is asynchronous.
- A lambda with several statements, because the rule only looks at a lambda that returns one expression.

The same sentence written as a conditional is [WYZ0119](WYZ0119.md), and a `ValueOr` whose value fallback does work is [WYZ0120](WYZ0120.md).

## Code fix

Yes. The fix renames the call and drops the success delegate. A cheap fallback that does not read the error becomes the argument itself
(`ValueOr(0)`, evaluated always); any other fallback stays the lambda. It works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0114.severity = warning   # or none
```
