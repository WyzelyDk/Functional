# WYZ0111: Do not interpolate values into the message of an error

| | |
|---|---|
| Category | Usage |
| Default severity | Warning |

## Cause

A message that is built with string interpolation, and has at least one value in it, is passed to a method of the library that creates or
passes on an error: the factories of `Error` (`Create`, `NotFound`, `Validation` and the others), `Result.Failure`, `WithContext`, and the
`message` of a railway method such as `Ensure`:

```csharp
return Error.NotFound($"Order {id} not found.");
return Result.Failure<Order>($"Order {id} not found.");
result.Ensure(order => order.Lines.Count > 0, $"Order {id} has no lines.");
```

## Why it matters

- The text is built every time the line runs. For `Ensure` and the other railway methods that is also when the result succeeded, so a
  success allocates a string that nobody reads.
- The value becomes part of the text. A message template (`"Order {id} not found."`) is the same for every order, so errors can be
  grouped and counted, and the value is still there as a detail for logging and telemetry.
- A detail can be marked as sensitive, so that the redacted output of the error hides it. A value inside an interpolated text is always
  visible.

## How to fix

Write the message as a template and pass each value as a detail:

```csharp
return Error.NotFound("Order {id} not found.").WithDetail("id", id);
return Result.Failure<Order>(Error.Create("Order {id} not found.").WithDetail("id", id));
return error.WithContext("Checkout of {id}", "id", id);
```

For a railway method, the form that takes a function for the error builds it only when the result failed:

```csharp
result.Ensure(order => order.Lines.Count > 0, order => Error.Validation("Order {id} has no lines.").WithDetail("id", order.Id));
```

## What is left alone

An interpolated text where every value is a constant, a text without a value, a message that is not interpolated, and the other texts
that take a string, such as `WithCode`.

## Code fix

Yes, for the factories of `Error`, `Result.Failure` and `WithContext`. The fix names each detail after the value (`id`, or `Id` for
`order.Id`), so rename a placeholder where a different name reads better. No fix is offered when it could not keep the message: a value
with a format or an alignment (`{price:N2}`), a value that is not a name or a member access, the same name twice, a verbatim or raw string,
and the railway methods, where the better form is the function shown above.

## When to change the severity

Make it quieter, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0111.severity = suggestion   # or none
```
