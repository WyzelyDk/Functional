# WYZ0120: Pass a function to ValueOr when the fallback does work

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A call of `ValueOr` that takes the fallback as a value, on a `Result<T>` or on a `Task` or `ValueTask` of one,
where the fallback calls a method or creates an object, an array or a collection:

```csharp
var customer = result.ValueOr(LoadDefaultCustomer());
var tags = result.ValueOr(new List<string>());
var label = result.ValueOr($"unknown {id}");
```

## Why it matters

The fallback is evaluated even when the result succeeded, because it is an argument. The call is made, or the object is allocated, and then thrown away.
A function is evaluated only for a failure.

## How to fix

Pass a function:

```csharp
var customer = result.ValueOr(() => LoadDefaultCustomer());
var tags = result.ValueOr(() => new List<string>());
var label = result.ValueOr(() => $"unknown {id}");
```

## What is left alone

What counts as work is a call of a method, the creation of an object, an array or a collection (`new`, `new[]`, `[1, 2]`),
and an interpolated string that is not a constant, found anywhere in the argument.
Reading a local, a parameter, a field, a property or a constant is not work.

- A fallback that cannot be moved into a function: one that awaits, passes something by `ref` or `out`, declares a variable (`out var n`, `is int n`),
  or reads a `ref`, `out` or `in` parameter, a `ref` local, a `Span<T>` or another `ref` struct, or the instance of a struct.
- A result of an `object`, a `Delegate`, a delegate type or an expression tree (and `dynamic`, to stay on the safe side): a lambda converts to those,
  so `ValueOr(() => 5)` would pick the overload that takes the value and return the function itself.
- The overloads that already take a function, and a call that is not written as `receiver.ValueOr(...)`.
- `ValueOr` of a type that is not `Result<T>`, for example a `Maybe<T>`.

## Code fix

Yes. The fix wraps the argument in `() =>`, and keeps an argument name if there is one. It works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0120.severity = warning   # or none
```
