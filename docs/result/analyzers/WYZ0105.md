# WYZ0105: Use EnsureNot instead of Ensure with a negated condition

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

An `Ensure` with a predicate that is a negation, and an error or a message:

```csharp
result.Ensure(order => !IsBlocked(order), Error.Forbidden("The customer is blocked."));
```

## Why it matters

`EnsureNot` rejects the value when the condition holds, so the negation disappears and the call reads like the sentence it stands for.

## How to fix

```csharp
result.EnsureNot(order => IsBlocked(order), Error.Forbidden("The customer is blocked."));
```

## What is left alone

A predicate that is not one single negation (`!a && b`), and the forms of `Ensure` that take a function for the error, which `EnsureNot` does not have.

## Code fix

Yes. The fix rewrites the call as shown, and works with "fix all in document, project or solution".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0105.severity = warning   # or none
```
