# WYZ0107: Use BindZip to keep the earlier value

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Bind` whose delegate maps the next result into a tuple of the value and the new value:

```csharp
result.Bind(quantity => PriceOf(quantity).Map(price => (quantity, price))).Map(pair => pair.Item1 * pair.Item2);
```

## Why it matters

That is `BindZip`: it keeps the value next to the value of the next step. The elements of the tuple are named `First` and `Second`, like those of `Zip`, and
`Map` and `Bind` can take the two values as separate parameters.

## How to fix

```csharp
result.BindZip(quantity => PriceOf(quantity)).Map(pair => pair.Item1 * pair.Item2);
```

## What is left alone

The tuple of the original has its elements named after the lambda parameters (`quantity`, `price`), and `BindZip` names them `First` and `Second`. So the rule
reports only when the very next call is a lambda that does not read those names. A tuple that is returned or assigned, three elements, or the elements in
the other order, are left alone.

## Code fix

Yes. The fix rewrites the call as shown, and works with "fix all in document, project or solution".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0107.severity = warning   # or none
```
