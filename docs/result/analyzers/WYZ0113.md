# WYZ0113: Use Tap instead of a Map that returns the value it was given

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Map` with a block body that does something with the value and ends with `return` of the same value:

```csharp
result.Map(order =>
{
    audit.Record(order);
    return order;
});
```

## Why it matters

That is what `Tap` is: a side effect on the value, which passes through unchanged. `Tap` says so, and the delegate has no `return` to forget or
get wrong.

## How to fix

```csharp
result.Tap(order =>
{
    audit.Record(order);
});
```

## What is left alone

A body that has another `return` before the last one, a body that assigns to the parameter, changes it with `++` or `--`, or passes it by `ref` or
`out` (the value that comes out is then not the value that went in), a body that returns something else, and an `async` delegate.

## Code fix

Yes. The fix renames the call and removes the last statement, and works with "fix all".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0113.severity = warning   # or none
```
