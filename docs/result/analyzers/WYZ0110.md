# WYZ0110: Use MapTry instead of Result.Try inside Bind

| | |
|---|---|
| Category | Design |
| Default severity | Info (a suggestion; it never breaks a build) |

## Cause

A `Bind` whose delegate runs a function inside `Result.Try`:

```csharp
result.Bind(text => Result.Try(() => int.Parse(text)));
```

## Why it matters

`MapTry` is that: apply a function to the value, and turn an exception into a failed result, in the same way `Result.Try` does (a cancellation keeps travelling
unless `ShouldCatch` says otherwise). A handler for the error is passed on as it is.

## How to fix

```csharp
result.MapTry(text => int.Parse(text));
```

An asynchronous function keeps its `async`.

## What is left alone

`Result.Try` with an action (it has no value, so there is no `MapTry`), `Result.Try` with a handler for one named exception type (`MapTry` catches an
`Exception`, so the rewrite would not compile), and a `Try` that is followed by another call.

## Code fix

Yes. The fix rewrites the call as shown, and works with "fix all in document, project or solution".

## When to change the severity

The rule is a suggestion, so it shows up in the editor and not in the build output. Make it louder, or switch it off, in `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.WYZ0110.severity = warning   # or none
```
